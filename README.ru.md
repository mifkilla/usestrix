# usestrix

Интерактивная обёртка над [Strix](https://github.com/usestrix/strix) —
автономным агентом для тестирования на проникновение.

Strix мощный, и его CLI честно описывает, что делает. Но несколько умолчаний
легко прочитать неверно, а неверно прочитанное умолчание стоит реальных денег.
Обёртка подставляет разумные значения, показывает ход работы и хранит след
каждого запуска.

*Проект независимый, к авторам Strix отношения не имеет. Лицензия MIT.*

*English version: [README.md](README.md)*

## Зачем это нужно

Пять вещей, на которых спотыкаются чаще всего:

| Что | Чем бьёт |
|---|---|
| `--scan-mode` по умолчанию **deep** | Забыл флаг — получил 1-4 часа работы и десятки долларов |
| `--max-turns` считается **на каждого агента** | Агентов в прогоне несколько, значит `100` может означать 500 ходов суммарно |
| `--max-budget` проверяется **после** ответа модели | Небольшой перерасход нормален; субагенты сворачиваются около 90%, чтобы корневой успел дописать отчёт |
| Код возврата **2** означает *найдены уязвимости* | Это не сбой. CI, считающий ненулевой код поломкой, отчитается неверно. С Strix 1.7 `--fail-on` гейтит код 2 по критичности |
| Локальный каталог монтируется **с правом записи** | Strix запускает приложение, в рабочем дереве появятся новые файлы |

`usestrix` делает каждый из этих пунктов видимым, а не внезапным.

## Что умеет

- **Мастер с пятью заготовками** — быстрый triage, веб-приложение, API по
  спецификации, исходный код, релизный аудит. У каждой заготовки записано
  *основание* её чисел, чтобы они не устарели молча.
- **Живая панель прогресса** — в headless-режиме Strix замолкает после
  баннера; панель показывает текущий ход, активного агента, проверенные
  поверхности, записи в SARIF и расход.
- **Веб-просмотрщик открывается сам** — ссылка печатается при старте скана и
  сохраняется в `viewer-url.txt`. Он работает на *идущих* прогонах, а не
  только на законченных.
- **Мягкая остановка** — `Ctrl+C` или пункт меню из второго терминала.
  Сначала `SIGTERM`, чтобы Strix сохранил уже найденное.
- **Продолжение прогона** — выбрать прежний и продолжить с новым бюджетом.
- **Гейт возврата по критичности** — спросит, передавать ли `--fail-on`
  из Strix 1.7 (headless-прогоны: код 2 только для находок выбранной
  критичности и выше).
- **Сводка находок** — сортировка по критичности, с CVSS и уверенностью.
- **След для аудита** — каждый запуск пишет `command.txt`, `scope.md`,
  `instruction.md`, `strix.log`, `status.txt`.
- **Английский и русский** интерфейс.

## Требования

- Python 3.9+
- Установленный и рабочий [Strix](https://github.com/usestrix/strix)
  (`pipx install strix-agent`)
- Запущенный Docker — Strix нужен он для песочницы
- `rich` для красивого вывода — необязателен, без него обёртка переходит на
  простой текст

## Установка

```bash
git clone https://github.com/mifkilla/usestrix.git
cd usestrix
./install.sh
```

Установщик кладёт один файл в `~/.local/bin/usestrix` и проверяет требования.
Удалить: `rm ~/.local/bin/usestrix`.

Вручную работает не хуже:

```bash
install -m 755 usestrix.py ~/.local/bin/usestrix
```

## Настройка

Обёртка читает конфигурацию самого Strix, своей не заводит. Модель и ключ
ищутся в таком порядке:

1. переменные окружения
2. `~/.strix/env`
3. `~/.strix/cli-config.json`

⛔ **Модель и ключ держать ВМЕСТЕ.** Strix выбрасывает сохранённую модель,
когда оболочка подаёт ключ от другого соединения — это его защита от
смешивания провайдеров (`config/loader.py`, `_drop_stale_llm_connection`).
Простейшая рабочая настройка:

```bash
# ~/.strix/env   (chmod 600)
export STRIX_LLM=openrouter/deepseek/deepseek-v4.1-flash
export LLM_API_KEY=sk-or-...
```

Переменные самой обёртки:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `USESTRIX_HOME` | `~/strix-runs` | Где живут прогоны и следы работ |
| `USESTRIX_VIEWER_PORT` | `3400` | Первый порт для просмотрщика |
| `USESTRIX_LANG` | `en` | `en` или `ru` |
| `STRIX_CONFIG_DIR` | `~/.strix` | Где искать конфигурацию Strix |

Чтобы интерфейс был русским постоянно, допиши в `~/.bashrc`:

```bash
export USESTRIX_LANG=ru
```

## Как пользоваться

```bash
usestrix
```

Обёртка начинает с проверки готовности — бинарь Strix, демон Docker, образ
песочницы, модель, ключ, свободное место — и не даёт продолжить, если чего-то
обязательного нет.

```
  OK  strix         strix 1.6.2
  OK  docker        демон отвечает
  OK  образ         скачан
  OK  модель        openrouter/deepseek/deepseek-v4.1-flash
  OK  ключ          задан, в команду не попадает
  OK  диск          702 ГБ
```

Дальше меню: новый скан, продолжить, показать находки, веб-просмотрщик,
остановить идущий скан, справка.

Во время скана видна живая панель:

```
            идёт скан  3м 12с
  ход              19
  агент            Recon & Surface Mapping
  поверхностей     4
  записей в SARIF  9
  расход           $0.4212
  остановить       Ctrl+C (мягко)
```

## Что остаётся после прогона

```
$USESTRIX_HOME/
  engagements/<метка>_<имя>/
    command.txt        точная команда, воспроизводимо
    scope.md           цели, режим, потолки, какая заготовка и почему
    instruction.md     что именно сказали агенту
    strix.log          полный вывод
    status.txt         код возврата и длительность
    viewer-url.txt     ссылка просмотрщика для этого прогона
  strix_runs/<прогон>/  собственный вывод Strix
    vulnerabilities.json
    penetration_test_report.md
    findings.sarif     level: error = critical и high, warning = medium
    coverage.json      что проверено, а что нет
```

## Как читать находки

У находки есть не только критичность. Два поля стоят дороже остальных и
обычно остаются незамеченными:

- **`counterevidence`** — что Strix проверял *против* собственной находки.
  Пустое поле означает слабую находку.
- **`coverage.json`** — что НЕ проверялось. Пробел в покрытии, поданный как
  «чисто», — это ложный отчёт.

Фильтровать по уверенности полезнее, чем по критичности:

```bash
jq '[.[] | select(.confidence == "high" and .cvss >= 7.0)]' \
  "$USESTRIX_HOME"/strix_runs/*/vulnerabilities.json
```

## Безопасность

- В ссылке просмотрщика **есть токен**. Кто её получит, сможет управлять живым
  сканом и читать историю. Никому не пересылать, на `0.0.0.0` не поднимать.
- Сканировать **копию** кода — отдельный git worktree или свежий клон. Обёртка
  спрашивает, но проверить за тебя не может.
- Тестировать только то, на что есть разрешение. Обёртка пишет периметр в
  `scope.md`, чтобы граница осталась на бумаге, но саму границу задаёшь ты.
